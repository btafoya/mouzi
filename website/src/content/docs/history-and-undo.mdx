Successful operations are recorded locally with paths, rule, time and organization run. History is not synchronized between computers.

## Find and undo operations

Open **Settings → History**. Filter by filename, rule, extension or a date/time range in your local timezone. Use **Show more** to display additional results. Runs identify manual organization, approved previews, automatic watching, scheduling or archive import.

Select entries or **Select this run**, choose **Review undo**, then confirm. Each file receives its own result. Pause the watched folder first if you are investigating an unexpected organization run.

Mouzi skips restoration when the original path is occupied, the organized file changed, or the file is unavailable. It never overwrites an existing source file. Restored files are protected from immediate automatic reorganization until their contents change; you can still explicitly select them in a preview.

An undo batch cannot recreate missing files. Restore skipped files manually after checking both locations.

## History from older versions

Older entries remain under **Earlier history**. They lack the verification records used by 0.2.0, so Mouzi cannot safely undo them. Restore those files manually. New move and rename records support verified undo.

## Recycle Bin and Trash

Trash actions are recorded, but restoration is handled through the system Recycle Bin/Trash. They are not eligible for Mouzi undo.

## Clear or back up history

Clearing History asks for confirmation, then removes the records and the ability to undo those operations in Mouzi. It does not move, restore or delete the files themselves.

To back up History, quit Mouzi and copy `mouzi.db`. It also contains settings, rules and watched folders. See [Settings and local data](/docs/settings-and-data) for paths.
